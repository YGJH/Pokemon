# RL_SPEC.md — Self-Play RL on top of the IL policy

**Status:** draft for review. Nothing here is implemented yet.

**Reading order:** `AGENT_SPEC.md` (engine I/O) → `TRANSFORMER_IL_SPEC.md` (model, tensors) →
this document. Where this document and `TRANSFORMER_IL_SPEC.md` disagree about
tensor layout or the `agent()` contract, **TRANSFORMER_IL_SPEC.md wins** — RL changes
how the policy is *trained*, not what it consumes or emits.

---

## 0. Goal and scope

Take the per-deck IL specialists (archetype 0 and archetype 2) and improve them by
self-play and cross-play, using PPO with an MCTS-derived improvement signal, while
anchoring to the IL policy with a KL penalty so the learned behaviour cannot collapse.
Promote a new checkpoint only when it clears a **≥70% score against the current
champion** and passes an IL-regression check.

**In scope:** rollout infrastructure, critic repair, PPO, KL anchoring, determinized
MCTS, a two-deck league, and the promotion gate.

**Out of scope:** deck construction (the deck stays fixed and label-pinned per
`ptcg_il/deck.py`), changes to `featurize()`, changes to the `agent()` contract.

## 1. Prerequisite: the value head is dead

**This blocks everything else and must be fixed first.**

`ValueHead` is `tanh(Linear(D,D) → GELU → Linear(D,1))` on `h_CLS`, so its range
`(−1, 1)` already matches a ±1 game outcome. But measured on the current arch-2
checkpoint:

| statistic | value | healthy |
|---|---|---|
| prediction std | 0.0006 | ~0.5–0.9 |
| target std | 0.994 | — |
| corr(pred, target) | 0.045 | > 0.4 |
| sign agreement | 0.556 | > 0.65 |
| MSE | 0.9988 | < 0.7 |

The head has collapsed to the constant ~0 — the MSE-minimising answer when the input
carries no usable outcome signal. PPO's advantage estimate is
`A_t = δ_t + γλ·δ_{t+1} + …` with `δ_t = r_t + γV(s_{t+1}) − V(s_t)`. With `V ≡ 0`,
GAE degenerates to the raw terminal return for every state in the episode — i.e. plain
REINFORCE with no variance reduction, across episodes of ~150 decisions. That will not
learn at a usable sample cost.

**Phase R1 (§8) is a critic-only repair phase.** Candidate causes to test in order:

1. **`h_CLS` carries no outcome information.** IL trains CLS only through the value
   loss (the pointer head reads the option/state tokens), so a `λ_v` of 0.5 against a
   dominant CE may never shape it. *Test:* freeze the trunk, train only `ValueHead`
   on the IL corpus; if it still collapses, the trunk is the problem, not the head.
2. **tanh saturation / dead gradient at init.** *Test:* inspect pre-activation std.
3. **Label noise.** Every decision point in a game shares one ±1 label, so early-game
   states are near-unpredictable by construction. Expected ceiling is well below 1.0
   correlation; judge against a per-turn baseline, not against 0 loss.

**Exit criterion for R1:** on held-out IL test data, `corr(pred, outcome) ≥ 0.35` and
prediction std ≥ 0.3, with the curve rising monotonically in turn number (late-game
states must be predicted better than early-game ones).

If the IL corpus proves too small (37,421 decision points), fit the critic on
self-play data generated by the frozen IL policy instead — cheap, unlimited, and
on-distribution for RL.

## 2. Environment contract

### 2.1 Terminal signal and reward

`Observation.current.result: int` is the **winning player index, or −1 if the battle
has not finished**. This is the only reward source.

```
r_t = 0                                     for all non-terminal t
r_T = +1  if result == our_player_index
      −1  if result == opponent index
       0  if the game ends without a winner (draw / truncation)
```

- `γ = 1.0`. Episodes are finite (~150 decision points observed) and there is no
  reason to discount a win. Use `γ = 0.997` only if truncation turns out to be common.
- `λ_GAE = 0.95`.
- **Optional shaping.** Prize-count differential may be added as *potential-based*
  shaping, `F(s,s') = γΦ(s') − Φ(s)` with `Φ = (opp_prizes_taken − our_prizes_taken)/6`.
  Potential-based shaping provably preserves the optimal policy; any other shaping
  does not, and must not be used.

### 2.2 Timeouts count as losses

`Observation.remainingOverageTime` is real. A rollout worker that exceeds the budget
must record the game as a loss, not discard it — otherwise training silently selects
for slow policies. MCTS iteration counts (§5) must be budgeted against this.

### 2.3 Process model

`cg/api.py` exposes a module-level `search_end()` and `sim.py` holds `libcg.so`
through a module-level `ctypes` handle, which strongly suggests **global engine
state**. Assume one game per OS process until proven otherwise.

> **R0 must measure this**, not assume it: attempt two concurrent `Battle` instances
> in one process. If they interfere, the vec-env is process-per-game; if they don't,
> threads are cheaper.

### 2.4 `ptcg_rl/env.py`

```python
class PTCGEnv:
    """One battle, one process. Wraps libcg.so behind a Gym-like surface."""

    def reset(self, our_deck: list[int], opp_deck: list[int], seed: int) -> dict:
        """Returns the first obs_dict requiring a decision from us."""

    def step(self, picks: list[int]) -> tuple[dict | None, float, bool, dict]:
        """Apply our selection, advance until it is our turn again or the game ends.

        Returns (obs_dict | None, reward, done, info). The opponent's decisions are
        taken by an opponent policy supplied at construction, so from the learner's
        view this is a single-agent MDP.
        """
```

The opponent policy lives *inside* the env. This keeps PPO single-agent and makes
league matchmaking (§6) a matter of choosing which opponent to inject.

## 3. The action is a *sequence*, not a token

This is the subtlest correctness requirement in the spec and the easiest to get
silently wrong.

A decision point has `minCount ≤ k ≤ maxCount` picks over ≤ `O_MAX = 64` options.
The IL model already handles this autoregressively with a STOP column
(`multiselect_ce` for teacher-forced training, `select_multi` for greedy inference).
For RL, one **action** `a = (a_1, …, a_k, STOP)` and therefore:

```
log π_θ(a | s) = Σ_{t=1..k+1} log softmax( mask( logits_t ) )[a_t]
```

- The sum **includes the STOP step** whenever a STOP column exists. Dropping it makes
  shorter selections systematically cheaper and biases the policy toward tiny picks.
- Rows where the expert/actor declined an optional select (`minCount == 0`, no STOP
  column emitted — 98 such rows exist in the IL corpus) contribute an empty sum.
  Handle explicitly; do not let them become `-inf`.
- The PPO ratio is on the **joint** sequence: `exp(log π_θ(a|s) − log π_θ_old(a|s))`.
  Per-step ratios are a different (and wrong) objective.
- Entropy is likewise summed over AR steps, masked to legal options.
- Already-selected options must be masked out at subsequent steps, exactly as
  `_select_multi_raw` does. **The mask used in rollout, in the PPO update, and in MCTS
  must be produced by one shared function.** Three copies will drift and the
  divergence will be invisible until the policy starts proposing illegal picks.

`ptcg_rl/actor.py` owns this:

```python
def sample_action(policy, batch, *, temperature=1.0, generator=None)
    -> tuple[list[int], torch.Tensor, torch.Tensor]:
    """Masked AR sampling. Returns (picks, logp_joint [1], entropy_sum [1])."""

def recompute_logp(policy, batch, actions) -> tuple[Tensor, Tensor]:
    """Teacher-force stored actions under current θ. Returns (logp_joint, entropy)."""
```

`recompute_logp` is a thin generalisation of the existing `multiselect_ce` — reuse it
rather than writing a parallel implementation.

## 4. PPO objective with an IL anchor

```
L = L_clip  +  c_v · L_value  −  c_H · H(π_θ)  +  β · KL( π_θ ‖ π_IL )
```

### 4.1 Clipped surrogate

Standard, with `ratio` on the joint sequence (§3):

```
L_clip = −E[ min( ratio · Â,  clip(ratio, 1−ε, 1+ε) · Â ) ],   ε = 0.2
```

Normalise `Â` per minibatch. Because episode length varies by ~3×, normalise over the
*batch of decision points*, not per episode.

### 4.2 Value loss

`L_value = E[(V_θ(s) − V_target)²]`, `V_target = Â + V_old(s)`. Clip value updates
to `±0.2` around `V_old` (standard PPO value clipping) — with a freshly repaired
critic (§1) this matters more than usual.

### 4.3 KL anchor to the IL policy — the forgetting guard

`π_IL` is the **frozen** `ckpt-best.pt` for that deck (arch 0 or arch 2), loaded once
and never updated. Per decision point, summed over AR steps and masked to legal
options:

```
KL( π_θ(·|s) ‖ π_IL(·|s) ) = Σ_t Σ_{o legal} π_θ(o|s,a_<t) · log( π_θ(o|s,a_<t) / π_IL(o|s,a_<t) )
```

- **Direction matters.** `KL(π_θ ‖ π_IL)` (reverse/mode-seeking, the RLHF convention)
  penalises θ for putting mass where IL has none — it is the right choice for
  *anchoring*. `KL(π_IL ‖ π_θ)` would force θ to cover all of IL's mass, including
  IL's mistakes, and the IL policy here is only 0.54–0.75 non-trivial top-1.
- **β must be adaptive.** A fixed β is either inert or dominant. Use a dual update
  against a KL budget `κ`:
  ```
  β ← clip( β · exp( (KL_measured − κ) / κ · η_β ),  β_min,  β_max )
  ```
  with `κ = 0.02` nats per decision point, `η_β = 0.1`, `β ∈ [1e-4, 10]`.
- Compute both policies' logits on the **same** legal mask. They share the state, so
  the supports are identical by construction — assert it rather than assuming it.

**State the tension honestly:** the KL anchor is what prevents catastrophic
forgetting, and it is also what caps achievable strength. If the IL prior is weak, a
tight κ will hold the policy near a weak optimum. κ is the primary knob to sweep, and
§7's promotion gate is what settles the argument empirically. Expect to *loosen* κ
across generations (curriculum on κ), with the gate as the safety net.

### 4.4 Hyperparameters (starting points, all need sweeping)

| knob | value | note |
|---|---|---|
| rollout decision points / iter | 16,384 | ~110 games |
| minibatch | 1,024 | |
| epochs / iter | 3 | more overfits with a KL anchor already present |
| `lr` | 1e-5 → 3e-5 | **much** lower than IL's 3e-4: fine-tuning, not fitting |
| `ε` (clip) | 0.2 | |
| `c_v` | 0.5 | |
| `c_H` (entropy) | 0.003 | masked-AR entropy is larger than single-token; start low |
| `κ` (KL budget) | 0.02 nats | primary knob |
| `γ`, `λ` | 1.0, 0.95 | |
| grad clip | 1.0 | as IL |
| sampling temperature | 1.0 train / greedy eval | |

## 5. MCTS: determinized search, used for targets not for acting

### 5.1 This is an imperfect-information game

`cg.api.search_begin` requires the caller to **supply predicted hidden information**
(opponent deck, prizes, hand, active). There is no perfect-information simulator.
So "MCTS" here means **determinized search**: sample `K` full states consistent with
the observation, search each, and aggregate.

**The belief problem is unusually easy here and we should exploit it.** The opponent's
deck is one of the six known 𝒟_opp archetypes in `archetypes.json`
(`opp_ids = [0, 2, 1, 3, 5, 9]`), so the belief over opponent deck is a **6-way
categorical**, not an open-ended distribution:

```
P(deck_j | observed cards) ∝ P(deck_j) · Π_{c observed} P(c | deck_j)
```

with `P(deck_j)` the mined `frequency` and the likelihood from the archetype's
representative multiset. Any observed card absent from `deck_j` zeroes that
hypothesis. In practice this collapses to near-certainty within a few turns.

`ptcg_rl/belief.py` owns this posterior. Note the existing `ptcg_il/model/belief.py`
is a *learned* history encoder feeding the trunk — different thing, keep both, don't
conflate the names.

**Name the known weakness:** determinized search suffers *strategy fusion* (it may
assume different actions in states it cannot distinguish) and *non-locality*. It will
systematically overvalue lines that depend on knowing hidden state. Do not present
MCTS values as ground truth.

### 5.2 Why MCTS must not simply pick the action

The naive design — "MCTS chooses the move, PPO learns from it" — is **mathematically
invalid**. PPO's ratio `π_θ(a|s)/π_θ_old(a|s)` presumes `a ~ π_θ_old`. If MCTS chose
`a`, the behaviour policy is the search-improved `π_MCTS`, the ratio is not an
importance weight for anything, and the update is biased in a way that no amount of
tuning fixes. This is worth stating explicitly because the bug is silent: training
runs, loss decreases, and the policy drifts wrongly.

Three coherent designs:

| | acting | learning | verdict |
|---|---|---|---|
| A. AlphaZero | MCTS | CE to visit counts | sound, but drops PPO |
| B. PPO-only | `π_θ` sampled | PPO | sound, cheap, no search signal |
| **C. PPO + search distillation** | `π_θ` sampled | PPO **+** auxiliary distillation to MCTS targets | **recommended** |

### 5.3 Recommended: design C

- **Acting (the PPO stream):** always sample from `π_θ` with masking. Ratios stay
  valid. Rollouts stay cheap.
- **Search targets (auxiliary):** on a sampled fraction `ρ = 0.05` of decision points,
  run determinized MCTS to produce an improved distribution `π̃` (visit counts,
  aggregated over `K` determinizations) and a value estimate `Ṽ`. Add:
  ```
  L_search = c_π · Σ_o π̃(o) log π_θ(o|s)  (cross-entropy, sign as loss)
           + c_ṽ · (V_θ(s) − Ṽ)²
  ```
  with `c_π = 0.3`, `c_ṽ = 0.3`. This is off-policy *supervised* distillation, so it
  composes with PPO without breaking the on-policy ratio.
- **Deployment:** MCTS *may* be used at inference if the time budget allows — but the
  promotion gate (§7) must then be measured with MCTS enabled, because the gate has to
  evaluate the artifact that actually plays.

`ρ = 0.05` because search is ~100× a forward pass; budget it explicitly against R0's
measured throughput rather than picking a number and hoping.

### 5.4 Reuse the existing Rust searcher

`python/ptcg_search/` already exposes a C-ABI `search_plan`:

```
search_plan(obs_json, lib_path, fixed_deck_json, opp_deck_json, iterations, seed)
    -> JSON {"indices": [...], "error": ...}     # free with search_plan_free
```

It currently returns only chosen indices. For distillation it must also return **visit
counts and the root value**. Extend the JSON to
`{"indices": [...], "visits": [[option, n], ...], "value": float, "error": ...}`
rather than writing a second searcher in Python. `live_eval.py` already loads this
library as a baseline — reuse its `_find_libcg_path()` discovery.

## 6. The league: two decks, cross-play and self-play

Each model owns a **fixed, label-pinned deck** (`ptcg_il/deck.py`), so a match is
always `deck_A` vs `deck_B`. Both archetype 0 and archetype 2 appear in `opp_ids`, so
cross-play is in-distribution for the IL prior — that is not luck, it should be
asserted at startup for any deck pair added later.

**Opponent pool per training iteration** (sampled per game):

| opponent | weight | purpose |
|---|---|---|
| current `π_θ` (mirror, same deck) | 0.30 | self-play |
| the *other* deck's current model | 0.30 | cross-play — the user's two-model fight |
| uniformly-sampled past champion | 0.25 | fictitious self-play; prevents cycling |
| frozen `π_IL` (same or other deck) | 0.10 | absolute anchor; detects regression |
| random-legal policy | 0.05 | sanity floor; must stay ~100% |

The past-champion slot is not optional. Two models training only against each other
will cycle (A beats B beats A′ beats B′…) and Elo will inflate with no real gain.

**Both models train concurrently**, each with its own PPO learner, optimizer, and KL
anchor, sharing a rollout pool. Alternating (freeze one, train the other) is simpler
and an acceptable first implementation — say which one you built.

**Elo** over all league games, with the frozen `π_IL` per deck pinned at 0 as the
reference. Cross-deck Elo mixes deck strength with policy strength; report per-pair
win-rate matrices too, not just a scalar.

## 7. Promotion gate: ≥70% score, and a forgetting check

A candidate replaces the champion for its deck **only if all four conditions hold.**

### 7.1 Match protocol

- **Opponent: the current champion for that deck**, not `π_IL`. Gating against the IL
  baseline saturates after generation 1 and stops being informative.
- **Paired games.** Every matchup is played twice with the same `seed` and the same
  determinization stream, swapping who goes first. First-player advantage in TCG is
  large; unpaired sampling wastes games on that variance.
- `n = 400` paired games (800 total).
- **Score, not raw wins:** `score = (wins + 0.5 · draws) / n`.
- Evaluated with the **deployment-time** inference procedure (greedy, or MCTS if
  MCTS ships), never the training-time sampling policy.

### 7.2 The four conditions

1. **`score ≥ 0.70`** — the user's bar.
2. **Wilson 95% lower bound ≥ 0.65** — the anti-noise floor. Necessary because a point
   estimate of 0.70 is compatible with a much weaker policy:

   | n (paired) | p̂ = 0.70 → Wilson 95% LB |
   |---|---|
   | 100 | 0.604 |
   | 200 | 0.633 |
   | **400** | **0.653** |
   | 1000 | 0.671 |

   At `n = 400` you need `p̂ ≈ 0.745` for the *lower bound* itself to clear 0.70. Pick
   your interpretation deliberately: the spec's default is "point ≥ 0.70 **and**
   LB ≥ 0.65 at n = 400". If you want "≥70% with 95% confidence", the bar becomes
   `p̂ ≈ 0.745` at n = 400, or n ≈ 1000 at `p̂ = 0.72`.
3. **IL-regression check — the real forgetting guard.** On the held-out IL **test**
   split for that deck, non-trivial top-1 must not fall more than **5 points** below
   the IL baseline (arch 0: 0.5394; arch 2: 0.7538). A KL penalty bounds *average*
   divergence; it does not guarantee the policy still handles the rare situations the
   corpus covers. This check does, and it is nearly free — the data already exists.
4. **`KL(π_θ ‖ π_IL) ≤ 4κ`** measured over the gate games. Catches a policy that
   satisfied the budget in expectation during training but drifted at evaluation
   temperature.

### 7.3 On failure

Do **not** discard the candidate. Keep training and re-gate — the gate is a promotion
criterion, not a training signal. Only the promoted checkpoint enters the league's
champion slot and the past-champion pool. If a candidate fails condition 3 while
passing 1 and 2, that is the signal to *tighten* κ, not to lower the gate.

### 7.4 Checkpoint format

Extend, do not replace, the `"deck"` record from `ptcg_il/deck.py` — the artifact
pinning (`vocab_sha1`, `archetypes_sha1`) is exactly as load-bearing under RL, and RL
checkpoints must remain loadable by `scripts/build_submission.py`.

```python
ckpt["rl"] = {
    "generation": 3,
    "parent": "rl-gen0002-arch2.pt",
    "opponent_pool": [...],          # what it actually trained against
    "gate": {
        "opponent": "rl-gen0002-arch2.pt",
        "n_paired": 400,
        "score": 0.7325,
        "wilson_lb": 0.686,
        "il_nontrivial_top1": 0.7401,   # vs 0.7538 baseline → −1.4 pts, passes
        "kl_to_il": 0.031,
        "passed": True,
    },
    "elo": 1187.4,
    "kappa": 0.02,
    "steps": 1_200_000,
}
```

`deck` stays untouched, so `--archetype-self` provenance and the submission builder's
deck-label lookup keep working unchanged.

## 8. Phases and exit criteria

Each phase has a falsifiable exit criterion. Do not start the next phase before the
current one passes — RL failures compound and become unattributable.

| phase | work | exit criterion |
|---|---|---|
| **R0** | `env.py`, `vec_env.py`, throughput + re-entrancy measurement. IL policy plays full games. | 1,000 consecutive games, **zero** illegal selections, zero engine crashes; games/sec/core recorded; process-vs-thread question answered |
| **R1** | Critic repair (§1) | `corr(V, outcome) ≥ 0.35`, pred std ≥ 0.3, accuracy rising in turn number |
| **R2** | PPO + KL anchor, **one** deck, self-play only, no MCTS | ≥ 60% vs frozen `π_IL` over 400 paired games, IL-regression < 5 pts |
| **R3** | MCTS: extend Rust searcher for visits+value, belief posterior, distillation loss | search-distillation ablation beats R2 by ≥ 3 pts at equal wall-clock |
| **R4** | Two-deck league, cross-play, Elo, promotion gate | one promoted generation per deck clearing all four §7.2 conditions |

R2 is the real go/no-go. If PPO with a KL anchor cannot beat the frozen IL policy on a
single deck with self-play alone, adding MCTS and a league will not rescue it — it
will only make the failure harder to diagnose.

## 9. Module layout

Mirrors the existing two-package convention. New third package `ptcg_rl/`, PyTorch-dependent.

| module | role |
|---|---|
| `config.py` | `RLConfig` dataclass — every knob in §4.4, §5.3, §7 |
| `env.py` | `PTCGEnv`: one battle, one process; opponent policy injected |
| `vec_env.py` | `N` parallel workers, batched inference to one GPU actor |
| `actor.py` | masked AR sampling, `sample_action` / `recompute_logp` (§3) — **single source of truth for masking** |
| `rollout.py` | trajectory collection, GAE, advantage normalisation |
| `ppo.py` | clipped surrogate, value loss, entropy, adaptive-β KL anchor (§4) |
| `search.py` | determinized MCTS via the Rust `search_plan`; visit/value aggregation |
| `belief.py` | 6-way categorical posterior over 𝒟_opp (§5.1) |
| `league.py` | opponent pool, matchmaking, Elo, past-champion archive |
| `gate.py` | paired-game evaluation, Wilson bound, IL-regression check (§7) |
| `train.py` | CLI: `python -m ptcg_rl.train --deck-archetype 2 --il-ckpt …` |

Tests in `python/tests/test_rl_*.py`, matching the existing layout. The engine must be
injectable (as `download.py` injects the Kaggle API) so tests need no `libcg.so`.

## 10. Risks

| risk | severity | mitigation |
|---|---|---|
| **Dead value head** | **blocking** | §1 / phase R1; do not start R2 without it |
| **MCTS-acts-and-PPO-learns bias** | **high, silent** | design C (§5.2); act only from `π_θ` |
| Multi-select logp computed per-step instead of joint | high, silent | §3; one shared masking function; assert `logp` reproduces `multiselect_ce` on IL data |
| KL anchor caps strength | medium | κ curriculum, gate as arbiter (§4.3) |
| Determinization bias (strategy fusion) | medium | acknowledged (§5.1); MCTS is a target, not an oracle |
| Two-model league cycles | medium | past-champion slot at weight 0.25 (§6) |
| Rollout throughput too low for PPO | medium | R0 measures it before any learning code is written; `ρ` budgeted against it |
| Engine global state / non-reentrancy | medium | assume process-per-game until R0 proves otherwise |
| Timeout losses select for slow policies | low | §2.2: record as losses |
| Reward hacking | low | reward *is* the objective (win/loss); nothing to hack |

## 11. Open questions for review

1. **Concurrent or alternating** training of the two deck models? Concurrent is truer
   to "these two fight each other"; alternating is much easier to debug.
2. **Does MCTS ship at inference**, or is it training-only? This decides whether the
   gate runs with search enabled, and it interacts with the Kaggle time budget.
3. **κ curriculum:** fixed 0.02 throughout, or loosened per promoted generation?
4. **Is 0.70 a score or a win rate?** The spec assumes score (draws count 0.5). If
   draws are impossible in this engine the distinction is moot — R0 should report
   whether any of the 1,000 games drew.
5. **Only two decks?** Row counts in `data/meta.parquet` (37,421 total):

   | archetype | rows |
   |---|---|
   | 0 | 15,002 ← specialist trained |
   | 2 | 8,481 ← specialist trained |
   | 9 | 5,083 |
   | 1 | 3,602 |
   | 5 | 3,189 |
   | 20 | 2,064 ← **zero val rows**, cannot be model-selected |

   Archetypes 9, 1, and 5 could seed further specialists, and a wider league cycles
   less. But every new deck multiplies rollout cost, so this is a phase-R5 question,
   not an R4 one.
